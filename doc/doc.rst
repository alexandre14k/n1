n1
==

Bare-metal Rust firmware for the NXP LPC1115 (Cortex-M0). Target
board is the OM13087. The firmware blinks the on-board LEDs in a
fixed sequence driven by one-shot timers.

Single binary crate. No std, no allocator, no runtime. Flat global
scope: every item name is globally unique by prefix convention.

Naming
------

Modules are private and re-exported flat with glob use. Rust
namespaces are not relied on. Collisions are prevented by name
alone.

===========  =================================================
Prefix       Layer
===========  =================================================
hal_core_    registers, bases, masks, mmio helpers, device data
hal_boot_    vector table, reset, irq hooks, critical sections
hal_driver_  clock, gpio, timer
app_         application layer
build_       build.rs helpers
===========  =================================================

Constants use the same prefix in upper case. Statics too.
Sub-modules extend the prefix: app_feature_pulse_,
app_interrupt_timer_, app_pinout_om13087_.

Layers
------

::

    main
      app   statemachine, feature, interrupt, queue, pinout
      hal   driver, boot, core

app depends on hal. hal never depends on app. main calls
hal_boot_init, app_statemachine_init, then loops on
app_statemachine_step.

Cargo features
--------------

========  ==============================================
Feature   Meaning
========  ==============================================
lpc111x   family. Required. Selects register map.
lpc1114   implies lpc111x. 32K flash.
lpc1115   implies lpc111x. 64K flash. Default.
========  ==============================================

build.rs panics when lpc111x is missing or no device is selected.
Profiles: dev uses opt-level 1 with debug info. release uses
opt-level z with lto and strip of debuginfo. Both abort on panic.

Build and flash
---------------

Everything goes through make.sh, an interactive menu.

======  ==================================================
Key     Action
======  ==================================================
b       release build, objcopy to bin, patch checksum, export
f       flash the built binary and verify
e       erase all flash sectors
x       exit
======  ==================================================

Settings:

- Target triple thumbv6m-none-eabi.
- CARGO_TARGET_DIR and TARGET_DIR are .target.
- Exported images land in bin/ as fw-<name>-<ddmmyy-HHMM>.bin.
- Firmware name is <device>-<name>-<version>.bin.
- Probe is CMSIS-DAP over SWD. Override with OPENOCD, OCD_IF,
  OCD_CFG.
- Flash base is 0x00000000.
- Without a tty, make.sh relaunches itself in xfce4-terminal.
- Toolchain setup is manual: rustup target thumbv6m-none-eabi,
  llvm-tools, cargo-binutils.

Vector checksum
~~~~~~~~~~~~~~~

The boot ROM requires the sum of vector words 0 to 7 to be zero.
After objcopy, make.sh sums words 0 to 6, negates the result and
writes it little endian at byte offset 28 (word 7). Word 7 is
reserved and zero in the vector table. A binary that skipped this
step will not boot.

Linker script
-------------

Generated by build.rs into OUT_DIR as link.ld and passed with
-Tlink.ld. Details are in src/link/link.rst.

- FLASH at 0x00000000. 64K for lpc1115, 32K for lpc1114.
- RAM at 0x10000000. 8K.
- .isr_vector is exactly 0xC0 bytes. The link fails otherwise.
- _estack is end of RAM minus 32 bytes. The ROM IAP uses them.
- The link fails if bss plus 0x200 stack bytes exceeds _estack.
- Entry is hal_boot_reset.

Boot
----

hal_boot_reset runs first. It copies .data from flash to RAM,
zeroes .bss, then calls main. The vector table is a static array
of 48 words in section .isr_vector:

- slot 0 initial stack pointer
- slot 1 reset
- slots 2, 3 fault, which spins forever
- slots 11, 14, 15 nop
- slots 16 to 47 one generic stub per IRQ 0 to 31
- remaining slots zero

Each stub is a const generic function that calls
hal_boot_irq_dispatch with its IRQ number.

IRQ hooks
~~~~~~~~~

HAL_BOOT_HOOKS is a table of 32 optional plain functions.
hal_boot_hook_set stores one. hal_boot_irq_dispatch calls the hook
for the IRQ, or disables that IRQ when none is set.
app_interrupt_hook_register sets the hook and enables the IRQ in
the NVIC.

Critical sections
~~~~~~~~~~~~~~~~~

hal_boot_critical_enter returns PRIMASK and masks interrupts.
hal_boot_critical_exit re-enables them only if they were enabled
at entry.

HAL
---

core
~~~~

lpc111x.rs holds the register map: SYSCON, IOCON, FLASHCTRL,
CT32B0, CT32B1, GPIO0 to GPIO3, NVIC set, clear and
clear-pending registers, clock gate bits, timer register offsets.
lpc1115.rs holds device data: memory sizes, port count and pins
per port (12, 12, 12, 6). mmio.rs holds volatile read, write, set,
clear, modify and bounded wait helpers.

clock
~~~~~

Runs from the 12 MHz IRC with AHB divider 1. Powers the IRC,
programs flash wait states by frequency, switches the main clock
source, enables boot gates (SYS, ROM, RAM, FLASHREG, FLASHARRAY,
GPIO, IOCON). Ticks per microsecond is hz divided by 1,000,000.
Returns false when the source switch does not complete within the
wait limit.

gpio
~~~~

IOCON offsets per port are table driven. Pins that reset to a
non-GPIO function (PIO0_0, PIO0_10, PIO0_11, PIO1_0 to PIO1_3)
are selected with function 1. Others use function 0. Output
writes use the masked data register trick: address bit 2 up
selects the pin. Direction is set per port in the DIR register.

timer
~~~~~

CT32B0 is index 2, CT32B1 is index 3. Prescaled to 1 us per tick.
One-shot mode uses MR0 with interrupt and stop on match. Start
stops, resets, loads PR and MR0, clears the interrupt flag and
enables the counter. Duration is in microseconds.

App
---

pinout
~~~~~~

Board data lives in pinout/om13087.rs and is reached through
app_pinout_ wrappers.

============  ====  ====  ================================
LED           Port  Pin   Note
============  ====  ====  ================================
red           0     7
green         0     8
blue          0     9
============  ====  ====  ================================

LEDs are active low. Reserved pins, refused by app_pinout_allowed:
PIO0_0, PIO0_10, PIO1_3, PIO0_4, PIO0_5.

Port codes are 0x0A plus the port number. decode and encode
helpers are provided.

queue
~~~~~

Single producer, single consumer ring of 16 slots, 15 usable. Each
slot is a u16: origin in the high byte, data in the low byte.
Interrupt handlers push. The main loop pops inside a critical
section. A full queue drops the event and push returns false.

Origins:

- APP_QUEUE_ORIGIN_TIMER 1, wait timer expired
- APP_QUEUE_ORIGIN_PULSE 2, pulse timer expired

interrupt
~~~~~~~~~

Two timer interrupts, CT32B0 for pulse and CT32B1 for wait. Each
handler clears the timer interrupt flag and pushes an origin to
the queue. No logic runs in interrupt context.

feature: pulse
~~~~~~~~~~~~~~

Drives one allowed pin to its active level for a width in
microseconds, then restores the idle level. One pulse at a time.
Start refuses when busy, when width is zero or when the pin is
not allowed. Release happens in app_feature_pulse_end, called by
the state machine on the pulse event. Uses CT32B0.

statemachine
~~~~~~~~~~~~

Sequence. Blinks are 100 ms, driven by the pulse feature. Waits
use the wait timer.

1. Blue blink at start.
2. Wait 2 s.
3. Green blink.
4. Wait 1 s.
5. Red blink, 100 ms gap, red blink.
6. Wait 1 s.
7. Back to step 3, forever.

States:

==========  ===========================================
State       Meaning
==========  ===========================================
FAULT       init or timer failure. Red LED on. Terminal.
BOOT_BLUE   blue blink
WAIT_GREEN  2 s wait, first pass only
GREEN       green blink
WAIT_RED    1 s wait
RED_FIRST   first red blink
RED_GAP     100 ms wait
RED_SECOND  second red blink
WAIT_LOOP   1 s wait, then GREEN
==========  ===========================================

Init order: clock, pinout (all LEDs off), timers. Then queue
reset, interrupt init, global interrupt enable, blue blink. Any
failure enters FAULT.

Dispatch: the main loop pops one event per iteration and routes
by origin to app_statemachine_pulse_done or
app_statemachine_wait_done. A pulse event ends the blink and
starts the next wait. A timer event starts the next blink.

panic
~~~~~

Panic masks interrupts and halts in a loop. No output.

Events
------

::

    CT32B0 irq -> app_interrupt_timer_pulse_isr -> queue PULSE
    CT32B1 irq -> app_interrupt_timer_wait_isr  -> queue TIMER
    main loop  -> app_queue_pop -> app_statemachine_event

Debugging
---------

Start openocd and gdb by hand. Useful registers:

========== ============================
Address    Register
========== ============================
0x40048070 MAINCLKSEL
0x40048080 SYSAHBCLKCTRL
0x40014004 CT32B0 TCR
0x40018004 CT32B1 TCR
========== ============================

A hang during boot is usually the clock source switch.
Build debug by hand with cargo for symbols.
